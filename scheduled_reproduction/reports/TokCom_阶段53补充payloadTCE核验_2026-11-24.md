# TokCom 阶段 53：补充 payload TCE 核验

这是新增的描述性解析补充，不属于第四十四阶段冻结主指标，也不修改原协议。计划、脚本身份和假设在本次读取 PHY 结果前记录于 `runs/stage53_payload_tce_plan.json`；原图像质量均值未用于制定该计划。

沿用上一阶段核对的 [论文第 VI 节](https://arxiv.org/html/2502.12096v4#S6) payload 定义：一次发送取 T=1，理想重传对照以 T=1/(1−PER) 代入 TCE=hw/(TN log₂Q)。这里的 T 包含首次发送。

## 输入与计算结果

使用现有全部 100 张图像、每张五轮、每轮 64 包的冻结物理缓存，合计 32,000 个包。100 个 token 编码文件与 500 个 PHY 文件均与原缓存审计的 SHA-256 一致。每包真实 payload 错误由发、收 token ID 比较确定，另独立读取 CRC 标记；固定交织和四 token 包映射均做了断言核对。

| 项目 | 结果 |
|---|---:|
| 真实 payload 错误包 | 2,227 / 32,000 |
| 真实 payload 错误包率 | 6.959375% |
| CRC 失败包 | 4,720 / 32,000（14.75%） |
| payload 正确但 CRC 失败包 | 2,493 |
| payload 错误但 CRC 通过包 | 本次观察为 0 |
| 接收错误 token | 2,639 / 128,000 |
| 一次发送的标称 payload TCE | 25.6 pixels/token-payload-bit |
| 理想重传对照的解析平均尝试次数 | 1.0747993148 |
| 理想重传对照的解析 payload TCE | 23.8184 pixels/token-payload-bit |

结果见 `runs/stage53_payload_tce_result.json`。该文件保存全部 500 组逐组计数和输入审计、计划、脚本、参考模块及原协议的哈希身份，没有读取图像质量指标或选择策略阈值。

## 解释范围

解析重传计算使用全体包的真实 payload PER，假设重复尝试独立且采用同一失败率。它不是实际运行过的重试次数、反馈状态机或时延测量，也不保证与每个包的条件错误概率完全一致。

payload 正确但 CRC 失败可能涉及接收校验位等差异，本报告仅陈述观察到的两类事件，不将其直接归因为实现缺陷。本次没有观察到错误 payload 通过 CRC，也不意味着其他接收条件下不可能出现该事件。

这些 TCE 值只按 token payload 计数，不包含 CRC、卷积码、调制填充、类别侧信道、ACK、控制包及时间成本。当前六条冻结重建路径复用同一次发送，不能单凭该标称值比较恢复质量或宣称已经复现完整论文 TCE 曲线。后续仍需完成图像指标、论文对照基线、CMI 消融和多 SNR 评估，并将工程资源账本分列。
