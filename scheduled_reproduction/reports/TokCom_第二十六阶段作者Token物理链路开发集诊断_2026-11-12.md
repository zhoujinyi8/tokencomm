# TokCom 复现：第二十六阶段作者 Token 物理链路诊断（2026-11-12）

本阶段把作者 VQGAN 权重重新编码的**真实开发集 token**送入上一阶段跑通的 Sionna 0.19.2 物理链路。取第 5 阶段开发集十类各第一张图，预处理固定为作者演示的 `Resize((256,256))` 加 `ToTensor()`；每图 256 个 token，固定交织成 64 包、每包 4 个 token，CRC11、短卷积码 `101/111`、16-QAM、AWGN 8 dB。每图做 5 次独立随机种子，共 **50 次传输 / 3,200 包**。

| 项目 | 50 次合计 |
|---|---:|
| 解码后数据 bit 错误 | 541 |
| 解码后 token 错误 | 265 / 12,800 |
| 作者演示的发收 token 比较：数据错误包 | **215 / 3,200（6.72%）** |
| 接收端 CRC 失败包 | **452 / 3,200（14.13%）** |
| CRC 失败但数据 token 正确的包 | **237** |
| CRC 未检出的数据错误包 | **0** |

五轮中，数据错误包数为 `48、40、50、40、37`，CRC 失败包数为 `95、78、96、87、96`。数据错误包与 CRC 失败包的差异与合成 token 的第二十五阶段结果方向一致。CRC 失败但数据正确可以由校验位损坏造成，不能称为 CRC 误报；本样本中没有观察到 CRC 漏检，也不表示一般情况下漏检概率为零。

记录文件 `runs/stage26_official_demo_tokens.npz` 保存作者 VQGAN 产生的 token 和图像哈希；`runs/stage26_official_token_link_snr8_5trials.npz` 保存 50 次传输的收到 token、真值比较遮蔽位、CRC 遮蔽位及逐次统计。已核验数组形状、非遮蔽位置发收 token 一致、token 错误总数与包统计一致。两份文件均为开发集资料，不是新的盲测集。

**边界：**物理链路使用作者演示相同的 Sionna 组件和参数，但 AWGN 随机数由 TensorFlow 生成，未逐样本复刻 notebook 的 PyTorch 随机数。当前还没有把收到的 token 送入作者 MaskGIT，也没有 PSNR、LPIPS、CLIP 或论文完整 TCE/反馈协议结果。下一步应在**完全相同的 50 次物理接收结果**上，分别用作者真值遮蔽和纯 CRC 遮蔽进行多步重建，比较图像质量与实际所需先验。
