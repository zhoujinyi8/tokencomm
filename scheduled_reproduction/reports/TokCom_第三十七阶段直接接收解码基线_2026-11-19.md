# TokCom 第三十七阶段：十图五轮直接解码基线

固定第 26 阶段接收 token，直接通过作者 VQGAN 解码，不做生成恢复。与前阶段相同原图、PSNR 原始输出口径、裁剪后归一化 LPIPS 和裁剪后 CLIP 配对。每张图先平均五轮，再对十张图求均值。

| 路径 | 正确 token /256 | PSNR dB | LPIPS ↓ | CLIP ↑ |
|---|---:|---:|---:|---:|
| direct | 250.70 | 18.8114 | 0.203389 | 0.808351 |
| oracle | 241.12 | 19.1311 | 0.199062 | 0.822604 |
| crc | 224.22 | 18.6058 | 0.211458 | 0.815336 |

逐图五轮均值中，优于直接解码的图像数：

{
  "oracle": {
    "tokens": 0,
    "psnr_raw": 9,
    "lpips_normalized": 8,
    "clip_clipped": 8
  },
  "crc": {
    "tokens": 0,
    "psnr_raw": 4,
    "lpips_normalized": 3,
    "clip_clipped": 5
  }
}

direct 为直接接收解码，oracle 为发送端真值比较遮蔽，crc 为接收端 CRC 失败遮蔽。三条路径使用相同接收数据。两种恢复方式掌握的信息不同；开发集十图不能用于论文总体性能推断，五轮复用同一图像。正确 token 数包含所有位置；其下降可来自恢复替换了原本已正确接收的 token。直接解码与恢复路径的指标输入定义一致，数值仅属于此固定开发协议。

机器结果见 runs/stage37_direct_baseline.json 与 runs/stage37_direct_comparison.json。
