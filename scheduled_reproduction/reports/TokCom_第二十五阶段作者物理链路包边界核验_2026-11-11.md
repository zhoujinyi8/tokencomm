# TokCom 复现：第二十五阶段作者物理链路包边界核验（2026-11-11）

本阶段按作者公开仓库固定提交 `0422ed32dcde3347e0bb6697f343f7a9ff7b3214` 的 `TokCom_Demo.ipynb`，对物理链路的包边界和错误判定做源代码核对，并为旧版 Sionna 接口建立独立运行环境。该环境与现有 PyTorch 模型环境分开，以避免依赖版本互相影响。作者 notebook 使用 `sionna.fec.crc`、`sionna.fec.conv`、`sionna.mapping` 的 TensorFlow 版接口；新版 Sionna 已换用不同的接口，因此复现需固定兼容版本。

演示实例有 256 个 10 bit token，按固定交织分成 64 包、每包 4 token。每包原始数据 **40 bit**，CRC11 后 **51 bit**，码率 1/2 的 `ConvEncoder(gen_poly=["101","111"])` 后 **102 bit**。全部 64 包共有 6,528 编码 bit，16-QAM 对应 **1,632 个符号**。每包 102 bit 不能独立整除 4；作者代码将所有包拼成比特流再按每 4 bit 调制，所以相邻两个包在边界共享一个 QAM 符号。解调后再把 6,528 LLR 按 64×102 切回包。这是源码规定的实际映射，应保留在精确演示复现中。

另一个边界是错误定位：`simulate_transmission` 虽执行 CRC 检查并生成 `crc_status`，后续 `calculate_errors(tx_ids, rx_ids)` 使用发、收 token 比较来标记错误包，然后让 MaskGIT 擦除这些包的 token。演示的擦除位置信息因此需要发送端真值；若改为仅按接收端 CRC 失败标记，属于另一种更现实的协议假设，结果必须分列。

独立链路脚本 `smoke_stage25_sionna_link.py` 用合成 token 做 64 包闭环，统计数据错误包与 CRC 检出包。独立环境安装了 TensorFlow 2.15.1、Sionna 0.19.2。Windows CPU 导入 Sionna 时，其可选射线追踪模块要求 `LLVM-C.dll`；脚本仅在导入时跳过该模块，FEC 与调制仍调用原版 Sionna。高信噪比 40 dB 自检在 20 组样本的全部 1,280 包上均无数据错误或 CRC 失败。

随后每档信噪比各用 20 个独立合成 token 与噪声种子，共 1,280 包：

| SNR | 数据错误包：发收 token 比较 | CRC 失败包 | CRC 失败但数据 token 正确 | CRC 未发现的数据错误包 |
|---:|---:|---:|---:|---:|
| 4 dB | 1,048 | 1,153 | 105 | 0 |
| 8 dB | 100 | 202 | 102 | 0 |

“CRC 失败但数据正确”可由校验位损坏造成，**不是 CRC 误报**。它说明演示中的真值比较遮蔽，与仅按 CRC 失败遮蔽，会在同一物理接收结果上选择不同的包。此处 20 组仅用于验证链路实现，不是论文数据集、信道曲线或统计置信区间。完整机器结果见 `runs/stage25_sionna_multiseed20.json`，单次烟雾检查见 `runs/stage25_sionna_link_smoke_v2.json`。
