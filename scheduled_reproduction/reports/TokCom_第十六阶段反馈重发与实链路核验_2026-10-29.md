# TokCom 论文复现：第十六阶段反馈重发与实链路核验（2026-10-29）

本阶段继续使用 stage5 的 **100 张开发验证图**、三个 Rayleigh 8 dB（Es/N0）数据链路种子，以及每张图最多 4 个数据包补发。接收端把 4 个包编号写入 24 bit 控制包，经过 CRC、卷积编码、16-QAM 和独立 Rayleigh 8 dB（Es/N0）反馈信道。若第一次反馈 CRC 失败，接收端在**假定超时**后再发一次；第二次仍失败则本轮不补发数据。每次 CRC 通过后都从解码后的控制 payload 读取包编号。六个反馈种子的运行均没有出现 CRC 通过而编号错误的事件，因此可以在编号完全一致时复用第十四阶段实际通过物理数据链路得到的补发结果。此处的超时没有建模时长。

## 主结果

下表使用反馈种子 `20261029`。命中率的分母均为三个数据链路种子上最初丢失的 **24,320 个 token**；随机策略是每张图、每个数据种子的五次抽样均值。

| 控制设置 | 低置信度选包 | 随机选包均值 | 两者差值 |
|---|---:|---:|---:|
| 首发后不补发数据 | 18.86% | 18.86% | 0 |
| 无反馈误码的理想交付 | 30.73% | 30.01% | +0.71 个百分点 |
| 编码反馈只发一次 | 28.16% | 27.32% | +0.85 个百分点 |
| 编码反馈最多发两次 | **29.88%** | **29.30%** | **+0.59 个百分点** |
| 编码反馈最多发三次（开发集开销探查） | 30.58% | 29.88% | +0.70 个百分点 |

最多两次时，低置信度控制请求最终通过 **279/300** 次，随机对照 **1,413/1,500** 次。相较只发一次，低置信度增加 **1.72 个百分点**，随机均值增加 **1.98 个百分点**。一次重发使控制失败引起的性能损失明显缩小；两种选包策略的差值也因此改变。

作为开销探查，最多三次时低置信度请求通过 **296/300** 次、随机对照 **1,483/1,500** 次。相对最多两次，低置信度命中率再增加约 **0.69 个百分点**，随机均值再增加约 **0.59 个百分点**；这是同一开发集上观察重试收益递减的结果，不能用来预先确定新留出集的最优重试次数。

按图像聚合三个数据种子和五次随机对照，再对 100 张图配对重采样 10,000 次，主反馈种子下差值的探索性 95% 区间约为 **[-0.01,+1.18] 个百分点**，包含零。换用 `20261029..20261034` 共六个反馈种子，差值范围为 **+0.58 至 +0.89 个百分点**。这些重复仍使用完全相同的图像与已保存的数据补发结果，不能视作六份独立测试集；单个反馈种子的重采样区间也没有覆盖反馈噪声的不确定性。

## 发送量

一个反馈尝试为 **23 个 16-QAM 符号**；反馈成功后四个数据包补发为 **124 个符号**。主反馈种子下，低置信度策略平均每图增加 **143.30 个符号**，相当于初始 1,984 符号的 **7.22%**；随机均值增加 **145.21 个符号**，约 **7.32%**。作为比较，只发一次控制包时这两个数分别是 **120.13** 和 **117.90**。反馈一次成功、第二次成功、两次均失败对应的增量分别是 **147、170、46 个符号**。这里比较的两种策略发送量仍不完全相同；不能将差值解释为严格等资源的策略优势。

最多三次的主种子平均增量分别为 **151.94** 和 **152.33 个符号/图**。这说明额外重试提高命中率的同时增加了控制发送量；本阶段尚未把等待时延折算进代价。

## 核验与边界

将新脚本设为最多一次反馈时，它的命中率和 CRC 通过次数与第十五阶段逐项一致。另在首个数据种子的全部 **100 张图**上运行完整首发、控制反馈、按解码编号补发、接收端再推理链路，逐请求比较实时链路和缓存重放：**200 次请求全部一致**，其中 **21 次**两次反馈都失败。前 10 张图的五次随机对照也逐项核验：60 次请求全部一致。实时结果与核验脚本收录于交付包。

主要复跑入口是在工程目录执行：

```powershell
python diagnose_stage16_feedback_retry.py --feedback-seed 20261029 --max-attempts 2 --out runs/recheck_stage16_summary.json
python summarize_stage16_feedback_retry.py
python verify_stage16_live_replay.py
```

第一个入口要求第十四阶段三个数据链路种子的逐图 JSON 已存在；实时核验还需公开预训练权重和本地缓存数据。交付包提供脚本、小体积 JSON 与逐文件 SHA-256 清单，不重新分发第三方大权重。

本阶段仍是本项目参考协议的**开发集诊断**，并非论文原始 TCE 方案。反馈重发采用理想超时触发，未计入超时时延、包头、导频、ACK、地址或控制误检后的恢复。公开预训练权重与 Imagenette 同属 ImageNet 生态，不能声称预训练数据严格不重叠。已看过的第十阶段留出集不能再用于新方法盲测。后续应先冻结控制协议与等资源评估办法，再准备新的项目独立留出集，同时补充感知或语义质量指标。
