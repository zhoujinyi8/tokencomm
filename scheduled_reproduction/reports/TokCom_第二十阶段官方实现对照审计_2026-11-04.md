# TokCom 论文复现：第二十阶段官方实现对照审计（2026-11-04）

本阶段找到并在本地只读检视作者公开的 [TokenCom_Code 仓库](https://github.com/liqiao19/TokenCom_Code)，固定提交 `0422ed32dcde3347e0bb6697f343f7a9ff7b3214`。仓库含 `TokCom_Demo.ipynb`、MaskGIT/VQGAN 网络与训练器、`Performance_metrics.py`，但不随仓库提供大权重或 ImageNet 图像。以下对照以该提交的演示代码为准，**不能自动等同于论文所有未公开的实验设置**。

审计脚本保存了 README、演示 notebook 和指标代码的 SHA-256，并对下表关键设置做源码断言，结果见交付包中的 `stage20_official_source_audit.json`。

| 项目 | 官方演示代码 | 本项目第九至十九阶段参考实现 |
|---|---|---|
| 每包 token 数 | 演示实例为 4 | 4 |
| 包内 token 分配 | 固定交织：第 `i` 个 token 放入第 `i mod 64` 包 | 每次运行用共享随机置换交织 |
| 物理信道 | AWGN | 主要结果使用 Rayleigh；另有 AWGN 参考诊断 |
| CRC | Sionna `CRC11` | CRC-16/CCITT-FALSE |
| 卷积码 | `gen_poly=["101", "111"]` | K=7，生成多项式八进制 `(171,133)` |
| 调制 | Sionna QAM，`num_bits_per_symbol=4` | Gray 16-QAM |
| 擦除位置 | 演示代码比较发、收 token，标出错误包 | 接收端根据 CRC 失败标出擦除包 |
| MaskGIT 生成 | 真实类别标签，32 步 `GenDecoding`，温度及调度见 notebook | 主要诊断是类别掩码前缀、一步预测 |
| 图像指标 | PSNR、LPIPS、CLIP 图像特征余弦 | PSNR 和冻结 ResNet18 特征代理指标；尚无原版 LPIPS/CLIP |

**关键结论：**当前参考链路的恢复率、PSNR 和重传收益不应与作者演示结果逐项数值比较。差异同时涉及信道、CRC/卷积码、交织、错误定位及生成步骤；单独改一项不会形成作者完整复现。尤其演示代码用发、收 token 比较确定错误位置，这相当于评估时可见真值；我们当前 CRC 判定是不同的接收端假设。两种设置需要分列报告。

在当前仓库提交中，未检出 TCE 计算、反馈 ACK 或重传策略实现。仓库 README 也将它描述为演示，主运行入口只评估重建 PSNR、LPIPS 和 CLIP。这个观察仅限于该提交，**不能据此断言论文不存在这些机制**。项目第十二至十九阶段的重传、反馈包头与超时规则仍是明确标注的项目参考设计。

权重对接也需要单独验证：官方 `Trainer/vit.py` 的加载器读取检查点字段 `model_state_dict`，本项目现有预训练 MaskGIT 文件的外层字段是 `state_dict`。这证明它**不能原样交给官方加载器**；目前没有验证参数映射或推理输出是否等价，不能靠改一个字段名就宣称兼容。

指标接入还有一个必须先核对的输入范围：[作者的指标函数](https://github.com/liqiao19/TokenCom_Code/blob/0422ed32dcde3347e0bb6697f343f7a9ff7b3214/Performance_metrics.py)把 LPIPS 输入截到 `[0,1]` 后直接调用模型；[LPIPS 官方实现](https://github.com/richzhang/PerceptualSimilarity/blob/master/lpips/lpips.py)的默认 `normalize=False` 要求输入已在 `[-1,1]`，而 `normalize=True` 才会把 `[0,1]` 转换过去。因此直接照抄作者演示函数与按 LPIPS 标准输入范围计算可能得到不同数值。后续评测应并列标注“演示函数原样”和“标准输入归一化”的结果，先验证差异再决定比较口径。

下一步实施顺序：

1. 先验证官方权重能否在本机加载，并在少量开发图上跑通官方演示的固定交织、AWGN、CRC11 与 MaskGIT 多步生成；记录原版权重、预处理及随机种子。
2. 接入作者 `Performance_metrics.py` 对应的 LPIPS 与 CLIP 指标，核对输入范围及预处理，再扩展到完整开发集。
3. 将官方演示路径和现有工程参考路径并列评估；明确哪个结果使用发送端真值定位错误，避免混称“接收端可实现”的恢复率。冻结后另设新留出集。
