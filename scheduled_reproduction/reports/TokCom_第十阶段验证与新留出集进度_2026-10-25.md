# TokCom 论文复现：第十阶段验证与新留出集进度（2026-10-25）

本轮把已校验码本的预训练 ImageNet-256 MaskGIT 接到现有 token 接收链路，完成完整 stage5 验证集比较，并冻结新的独立留出评估协议。**这仍是轻量 TokCom 接收端实验，不是原论文完整系统复现。**

## 开发验证：100 张图、固定信道种子 20261021

指标只统计被擦除位置的精确 token 命中率；所有方法在每个 PER 上共用同一擦除掩码。预训练模型均为一步 argmax，未擦除 token 保持不变。主方法把类别前缀也设为掩码 token `2024`，不传输真实类别；这偏离类别条件预训练的输入分布，但不会偷用真值标签。表中“真实类别”仅为有特权的诊断，不作为无侧信息结果。

| PER | 丢失 token | 预训练·类别掩码 | 预训练·真实类别 | 第七阶段小模型一步 | 空间填补 |
|---:|---:|---:|---:|---:|---:|
| 10% | 2,608 | 599 / 2,608 = **22.97%** | 23.77% | 1.38% | 2.22% |
| 30% | 7,652 | 1,533 / 7,652 = **20.03%** | 20.06% | 1.44% | 2.27% |
| 50% | 12,788 | 1,985 / 12,788 = **15.52%** | 16.33% | 1.27% | 2.06% |

另在 PER 30% 上测试接收端类别推断：从空间填补后的 token 解码图像，再用冻结的 ImageNet ResNet18 分类；100 张中类别正确 59 张，token 恢复为 1,543/7,652 = 20.16%。它与类别掩码的 20.03% 接近，却需要额外模型，因此没有选作主方法。

按**图像**而非 token 为单位做 10,000 次配对重采样，主方法相对空间填补的准确率差分别为 +20.74、+17.76、+13.46 个百分点；对应探索性 95% 区间为 `[18.62, 22.92]`、`[16.18, 19.37]`、`[12.28, 14.66]` 个百分点。这些区间只描述当前固定验证集实验，**不是独立测试的显著性结论**。

在 PER 30% 的类别分组检查中，10 个类别各自的类别掩码接收率都高于空间填补；改善并非由单一类别独占。这同样只是验证集诊断。

## 新留出集与冻结规则

从同一公开 Imagenette 验证数据源另抽取每类 10 张、共 100 张，预先排除 pilot、stage5、stage7 全部旧划分。新集合与旧集合的文件哈希和解码像素哈希交集均为零，新集合内部也无重复。原始数据源仍属于 Imagenette/ImageNet 生态，不能保证公开预训练模型从未接触同源图像。

在任何新留出 token 编码或评估前，已冻结 `runs/stage10_frozen_protocol/protocol.json`：主接收规则为“类别前缀 2024 掩码、一步 argmax、只填丢失 token”，包长 4 token，PER `0.1/0.3/0.5`，每档种子 `20261101..20261105`。协议还钉住了留出清单、tokenizer、预训练 Transformer、第七阶段检查点的 SHA-256，以及第三方 PyTorch 转换源码的提交。留出清单 SHA-256：`a323582848608f519dc131013efa1c583837a6e582681c5a9243f1541bb0526c`。

## 独立留出测试进度

新留出集评估可分段续跑。目前完成 **5/15 个预设案例**，即 PER 10% 的全部五个信道种子。累计丢失 token 为 12,792：预训练类别掩码接收端命中 2,911（**22.76%**），空间填补 275（**2.15%**），第七阶段小模型一步 174（**1.36%**）。五个种子重复使用同一批 100 张图，12,792 不能当成独立图像样本数；这里只做描述性汇总。PER 30% 和 50% 各五个案例仍未运行，因此**尚不能称为预设评估的最终结果**。可恢复进度与逐案例计数见增量包的 `stage10_holdout_progress.json`、`stage10_holdout_status.json` 和 `stage10_holdout_summary_partial.json`。

后续只能按同一协议续跑剩余 10 个案例，不利用已经看到的留出结果修改模型、类别处理、种子或指标。完成 15/15 后才能给出预先设定范围的最终汇总。

## 复现范围与材料

源码基于 [Google 官方 MaskGIT](https://github.com/google-research/maskgit) 的[第三方 PyTorch 推理转换](https://github.com/hmorimitsu/maskgit-torch)，提交 `40c45116cfe48b2c9fec1e038e635bfc45ed59f8`。转换版只支持推理；本轮没有训练或改动原预训练 Transformer。接收端的类别掩码用法、空间填补基线及包擦除流程均为本项目实验设定，不应说成论文原样实现。完整系统仍缺原文的自适应策略、反馈/重传链路与全套语义感知指标。

增量包提供自编脚本、冻结协议、验证结果 JSON 与可续跑的留出测试进度，不重新分发约 690 MB 的第三方权重或第三方源码。

交付前已运行 `python -m unittest discover -q`，22 项测试通过；增量包完整性及其中 100 张留出图、5/15 进度状态均已核对。
