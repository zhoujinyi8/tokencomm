# TokCom 第四十阶段：接收端 CRC 置信度门控开发对照

固定十张开发图、五轮 AWGN 8 dB 接收、真实类别与原作者生成候选。新门控只使用接收 token、CRC、已知类别和模型输出；发送端 token 只在决策后用于计分。使用同一份所有 CRC 失败位置同时遮蔽的上下文，比较候选 token 与接收 token 的 softmax 概率（logits 乘 1.3）。只有候选概率较高且达到预设门槛时才替换。门槛在运行前固定为 0、0.5、0.9，全部报告，未据开发结果选门槛。

直接接收正确总数为 12535。三档门控均减少了原 CRC 生成路径的替换和误改，但均未实现精确 token 净修复收益。0.9 门槛的三个替换均为误改，说明在此掩码上下文和候选选择下，模型概率不是已经校准的信道 token 正确率。此结论不能外推至其他门控方法或数据。

图像指标使用此前固定口径：PSNR 对原图直接比较原始解码输出；LPIPS 对裁剪图 normalize=True；CLIP 使用裁剪后 PIL 和 ViT-B/32。每张图先平均五轮再对十图平均。直接接收、原 CRC 恢复与门控使用相同接收数据；门控额外增加一次模型前向计算，尚未计入时延或资源等价约束。候选生成仍沿用原模型及固定采样种子，不是论文原始 TCE 实现。

数据仍为开发集十图的重复接收，尚未新盲测；本轮没有训练、校准或选择最终阈值。下一步应在开发集检查 CRC 失败包内的信道软信息能否支持更合适的保留策略，冻结策略后再准备新的留出评估。
