# TokCom 论文复现：第十三阶段物理重传开发验证（2026-10-29）

本轮把前一阶段的接收端低置信度选包策略接到现有参考数字物理层，在 stage5 开发验证图上运行一轮实际数据包重传。物理层使用卷积码、16-QAM、Rayleigh 衰落、软输入 Viterbi 与 CRC。反馈包编号假设可靠送达，**反馈开销、时延、包头和导频尚未模拟**；这仍不是论文完整反馈链路。

## 流程

每张图的 256 个 VQ token 经随机交织分成 64 个包，每包 4 token；每张图以“种子＋图像序号”生成独立交织与信道随机流。首发失败包按 CRC 标记丢失；接收端只用译码后 token 和丢失包位置运行类别掩码 MaskGIT。随后分别用低置信度策略或一次均匀随机选包，最多请求 4 个丢失包重传。两种策略共用同一首发结果，并从同一重传信道随机状态开始；由于所选包不同，结果仍会受到随机重传成败影响。重传成功包按 CRC 接收，失败包保持丢失，最后对剩余丢失 token 再运行一次 MaskGIT。发送端使用原始 token 形成数据包，真值仅用于最终计数，不作为接收端修复信息。

设置：100 张 stage5 开发验证图、Rayleigh、Es/N0=8 dB、种子 20261029、每图重传预算 4 包。

独立核对脚本对三个种子的首张图重新运行原有 `transmit_tokens` 接口，确认本轮显式分包循环得到的接收 token 与 CRC 擦除位置逐项一致。

## 结果

| 项目 | 数值 |
|---|---:|
| 首发包 | 6,400 |
| 首发 CRC 失败包 | 2,048（32.0%） |
| 最初丢失 token | 8,192 |
| 补发前 MaskGIT 命中 | 1,492 / 8,192 = **18.21%** |
| 低置信度补发 | 400 次尝试，268 次 CRC 通过；最终 2,469 / 8,192 = **30.14%** |
| 随机补发 | 400 次尝试，262 次 CRC 通过；最终 2,394 / 8,192 = **29.22%** |

低置信度策略比这**一次随机选包**高 **0.92 个百分点**。按 100 张图配对重采样 10,000 次，探索性 95% 区间约为 **[-0.14,+1.96] 个百分点**，包含零；逐图为 54 张更好、6 张相同、40 张更差。**单种子结果不能确认物理重传条件下该策略稳定优于随机选包。**与前一阶段“完美补发、随机对照精确期望”的结果不可直接等同。

每图 4 次补发尝试相当于原始 64 包之外增加最多 6.25% 的数据包发送次数。这个比率不含反馈信令与协议开销，也不等于完整系统吞吐率。

## 三种子补充检查

在同一 100 张图、相同 Rayleigh 8 dB 与每图 4 包预算下，再运行种子 `20261030`、`20261031`。两次低置信度策略分别比各自的**一次随机选包**高 **0.66、0.63 个百分点**；三个种子均为正。跨三种子共 24,320 个最初丢失 token，低置信度策略最终命中 **30.73%**，随机选包命中 **29.99%**，差值 **+0.74 个百分点**。同一批 100 张图被重复使用，按图像聚合三个种子后重采样得到探索性 95% 区间 **[+0.18,+1.31] 个百分点**。这比单种子结果更稳定，但随机对照仍只有每种子一次抽样，且全部属于开发集；不能据此宣称独立测试已证明策略优越。
